# 论文交互图解

默认交付一份可直接打开的 `论文导览.html` 和一份可以独立阅读的 `论文讲解.md`。
HTML 负责直观理解与逐层展开，Markdown 负责连贯讲解、公式解释和证据边界。默认中文。

## 阅读与证据

- 接受论文 PDF、原文链接、明确标题或节选。没有目标论文时先索取，不从工作目录随意挑选。
- 核对论文身份、版本与实际阅读范围。只有摘要或节选时明确限定范围，不标成完整论文导览。
- 全篇模式覆盖正文的主要论证顺序，并按需要读方法、实验与附录。实际查看支撑讲解的图表、图注、坐标与图例，不凭抽取文字猜图。
- 记录关键结论的章节、公式、图表或页码，以及数值、单位、比较对象和条件。区分作者主张、原文证据、解读者判断和未确认事项。
- 可复用当前可用的论文阅读、PDF 和图像能力；本技能不要求安装另一技能才能执行。

## 组织全篇 01–0n

阅读 [论文阅读框架](references/paper-reading-framework.md)，覆盖六部分阅读框架的内容范围和可辨认的小项；用户另有模板时优先遵循明确要求。
六部分是内容骨架，导航章节数由论文决定；较复杂的方法、基线或结果可以分别占一章。

- 章节用连续编号 `01`、`02`…`0n`，标题说明本章要解释的问题。章节同时标明它属于哪一类阅读内容。
- 首页展示论文信息、一句话总结、全篇关系和所有编号章节。每章只放一幅可读的小图与一句话，不将详细笔记堆在首页。
- 点击任意章节，在弹窗中展示更详尽的图形、对应模板小项、必要解释、适用条件与来源。展开必须增加理解所需的内容，不能只是放大首页缩略图。
- 同一模板部分拆成多章时，其小项在这些章节之间完整分配。例如“数据与标注”“方法过程”“基线怎么比较”可同属“研究设计与方法”。
- 章节编号与论文原章节号分别标识，不混淆。HTML、弹窗、Markdown 使用相同的导航编号与标题。
- 缺失、不适用和待确认保持可见；没有用户研究背景时，研究联系各字段标为待补充，不虚构关联。

用户要求按原文顺序时沿用原文阅读顺序；要求单图、局部更新或其他格式时尊重明确范围。
已有导览只改相关章节，同时更新对应 Markdown，不重新生成无关章节。

## 先画清关系，再写讲解

设计图形时阅读 [视觉制作指南](references/visual-production.md)。

- 每个图解围绕具体对象和操作，展示输入、关键变化、输出或比较关系。短标签配合图形，不用装饰图标替代解释。
- 基线展示共同设置、改变的部分和判断依据，让名称落在实际作用的位置；只画原文确认共用的条件。
- 训练与推理、预测与观测、更新与冻结、结果与示意需要能够辨认。模型名、颜色和对象形状在全篇一致。
- 保留影响解读的单位、指标方向、比较条件和不确定性；不给未知数据编造曲线或实例结果。
- 流程、结构、公式和关系明确的图优先采用 HTML/CSS、内联 SVG 或标准绘图。需要真实质感的解释性插画时使用可用图像工具；修改已生成位图时用图像编辑工具。
- 首页与弹窗可以使用不同层次的图：概览简图 → 详细流程或对照。精确科学图表依据核实数据生成，重要公式同时有文字解释。

## HTML 与 Markdown 的配合

制作时阅读 [交互导览与配套讲解](references/interactive-delivery.md)。

- HTML 默认自包含：内嵌样式、交互、SVG 或必要位图，不依赖网络字体、CDN、构建命令、后端或在线模型调用。
- 弹窗支持关闭、Esc、键盘导航与返回触发位置；手机可阅读、图解可放大、来源可打开。单文件移动后，章节与图解仍能工作。
- Markdown 是完整的讲解稿：说明问题为什么重要、方法怎样运行、关键公式与图表如何读、证据支持到哪里。不要只输出目录、图片链接或字段清单。
- Markdown 与 HTML 同编号同事实；HTML 中可下载相同的 Markdown。正文对概念作解释，长出处与补充条件集中于适当位置。
- 可以使用 [HTML 模板](assets/reader.html) 和 `scripts/build_reader.py` 生成两份文件。模板只提供交互外壳；实际图形、解释深度与章节设计应根据论文创作。
- 工作材料可以保留章节内容与证据记录；用户主要拿到 HTML 和 Markdown 两份成品。默认保存到独立输出目录，避免覆盖论文和已有图解。

## 检查与交付

1. 核对全篇覆盖、模板小项及缺项状态；复核关键数值、公式、比较条件和来源。
2. 实际打开所有图解，检查中文、图形、箭头及正常预览尺寸的可读性。弹窗增量信息应足够解释本章。
3. 在可用浏览器中验证首页、各章节弹窗、关闭与 Esc、上一章／下一章、图解放大、窄屏布局和 Markdown 下载。对静态校验与实际交互验证分别如实说明。
4. 检查 HTML 和 Markdown 的编号、标题、结论与来源一致；下载的 Markdown 与交付文件相同。
5. 交付两个文件的可点击链接，简要说明如何阅读与实际覆盖范围。能打开预览时展示 HTML；不要把整份 Markdown 再贴进聊天。

工具受限时说明具体未完成的检查或功能，不把文件存在或脚本成功当成渲染、交互或科学结论已验证。
