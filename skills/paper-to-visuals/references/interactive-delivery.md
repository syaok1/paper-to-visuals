# 交互导览与配套讲解

## 两份成品

- `论文导览.html`：可离线直接打开的单文件。首页总览全篇；点击 01–0n 进入对应弹窗。
- `论文讲解.md`：与网页相同的章节编号和事实，展开为可以独立阅读的中文讲解稿。

HTML 内置一份相同的 Markdown，可通过“下载讲解稿”取得。不要依赖读取旁边的 `.md` 文件或浏览器 `fetch`，以免直接打开本地 HTML 时失效。
Markdown 可链接回 HTML 的章节锚点；正文仍须自足，不以“请看图”代替解释。

## 每一章的三个层次

| 层次 | 内容职责 | 密度 |
|---|---|---|
| 首页卡片 | 本章讲什么；一个核心对象或关系 | 编号、标题、简图、一句话 |
| 章节弹窗 | 图形解释过程、对照、公式或证据 | 详细图、对应小项、必要条件和来源 |
| Markdown | 连贯讲清动机、推理、实施、结果与边界 | 根据理解需要展开，不机械限字 |

弹窗的视觉主内容与首页缩略图有明确层次差异。复杂内容可在一个弹窗内逐步展开；通常保持单层弹窗，避免叠套弹窗。
例如基线章的首页只显示“共同输入 → 两种方案 → 比较输出”，弹窗按具体实验分别展开共同设置、替换模块、判断依据。正文再解释哪些公平性条件得到确认、哪些没有交代。

## 章节同步与模板

模板 [reader.html](../assets/reader.html) 和脚本 [build_reader.py](../scripts/build_reader.py) 提供无需第三方库的交互外壳与双格式生成。也可以直接创作等价页面；无需为了套模板简化论文本身。

脚本读取一个 UTF-8 JSON。章节文字是两份成品的共同来源，图形由创作阶段提供。支持下列结构：

```json
{
  "title": "已核实的论文标题",
  "kicker": "论文图解",
  "subtitle": "年份、版本或简短副标题",
  "summary": "一句话总结",
  "scope": "实际覆盖的材料范围",
  "chapters": [
    {
      "id": "01",
      "title": "本章主题",
      "category": "对应的阅读框架部分",
      "summary": "首页一句话",
      "overview": {"path": "figures/01-overview.svg", "alt": "首页简图的文字含义"},
      "figures": [
        {"path": "figures/01-detail.svg", "alt": "详细图的文字含义", "caption": "示意性质、必要条件或图源"}
      ],
      "sections": [
        {"heading": "可辨认的模板小项", "paragraphs": ["必要解释"], "items": ["适合并列展示的要点"]}
      ],
      "explanation": ["本章连续讲解的第一段。", "第二段可解释公式、实施或证据边界。"],
      "sources": [{"label": "原文 §2 / 图1", "url": "https://example.org/paper"}]
    }
  ]
}
```

`overview`、`figures` 支持 SVG、PNG、JPEG、WebP。图片路径相对于内容文件；脚本将图像嵌入 HTML，不把本机绝对路径写入网页。空泛例图不能替代实际论文图解。
`sections` 的小项进入弹窗和 Markdown；`explanation` 在弹窗中可展开阅读，并作为 Markdown 的主体。公式可使用 Unicode 表示或作为核实后的 SVG 图；若需要复杂排版，可按任务扩展模板，确保离线可用。
研究联系等实际缺项可以用明确状态与文字替代无意义空图；不得借此省略有内容的章节图解。

运行：

```text
python3 <skill-path>/scripts/build_reader.py <content.json> --output-dir <独立输出目录>
```

首次生成不会覆盖已有成品；修改同一份已获授权的导览时，可加 `--replace`。替换参数只用于指定输出目录内的两份成品。
JSON 是工作材料，不必作为主要交付链接。脚本不会阅读论文、创造图解或验证科学结论，这些仍由创作过程负责。

## 交互与可读性

- 所有章节可从首页直接进入，也可在弹窗上一章／下一章连续阅读。
- 关闭按钮、Esc、焦点返回与键盘访问有效；链接不能被章节按钮吞掉。
- 详细图可放大并滚动查看；关闭后保留首页阅读位置。
- 小屏幕中卡片重排，正文自然换行。图形可在自己的区域横向滚动，页面本身不应被撑宽。
- 章节地址可定位到相应弹窗；不要将浏览器导航变成无法退出的历史循环。
- 不添加登录、上传、在线生成、账号或部署流程，除非用户明确要求这些功能。

## Markdown 的讲解标准

开头给出基本信息、阅读范围、一句话总结与章节索引；之后用相同的 01–0n 标题展开。
每章先用连贯段落建立理解，再提供必要的小项、公式解释、证据表或原文位置。根据论文实际内容决定篇幅，不要求每章机械使用相同段落格式。
方法解释应能让读者跟随一个样本理解过程；结果解释保留比较对象、单位、方向和条件；贡献与局限保留归属及证据边界。
即使看不到网页，Markdown 读者也应理解主要论证，不能只得到图片文件列表。

## 验证边界

实际验证至少包括：所有章节能打开、内容对应、关闭与 Esc、首尾章节切换、放大后还原、窄屏布局、Markdown 下载。
从数据源生成两个文件可以减少漂移，但仍需核对模型实际写入的事实与图形。静态检查、浏览器验证、原文核对各自建立不同的事实。
