# 论文阅读框架与图解对应

此框架沿用六部分论文阅读结构，并补充可视化表达、交互分层和证据核对要求。
阅读结构参考了设计过程中提供的模板，其来源标识为“论文标书的 Zoey_bilibili”。该标识用于致谢，不是目标论文标题或作者；仓库未收录原始模板文件。
下列六部分是全篇导览的内容骨架，不限定导航只有六章。首页按 01–0n 展示章节，弹窗保留所属部分与小项；完整图解时，每项都应有对应内容、已核实的不适用原因或待确认状态。短标题可以缩写，但字段含义不能丢失。
同一部分可拆成几个导航章节，编号与配套 Markdown 同步。例如“研究设计与方法”可拆为数据、方法和基线三章；不能因拆分而漏掉数据规模、条件或可获取资源等小项。

## 基本信息与一句话总结

记录能够核实的字段：文献编号（已有时沿用）、论文标题、作者或团队、年份、期刊或会议、DOI 或原文链接、文献类型、阅读状态。
没有文献编号时不用强行建立编号体系。阅读状态按实际材料覆盖记录；摘要已读不等于全文已读。
预印本和正式发表版本区分；缺失信息保持未确认。
总览或配套信息卡显示基本信息的短值。完整论文标题、DOI 和原文链接较长时放在紧邻图注，图中保留可识别的短标题和来源提示。

一句话总结回答：

> 在什么对象和条件下，作者用什么方法，发现了什么？

它用来确定总览图的主线；保留影响结论含义的条件，不能为简短而把特定实验概括成普遍成立。

## 1. 研究问题与背景

提取：

- 具体研究问题。
- 已有研究做到了什么。
- 仍然存在的不足。
- 作者提出的假设或目标。

适合的画法：同一场景下的已有做法与未解决问题，或“当前状态 → 受阻之处 → 希望达到的状态”。
研究目标与已实现结果用状态标识区分。论文未实际比较的先前工作，不画成已被实验证实落后的基线。
细节卡保留四个可辨识的小项：“研究问题”“已有进展”“仍有不足”“假设／目标”，可沿一个场景或过程展开。

## 2. 研究设计与方法

提取：

- 研究对象或数据来源。
- 样本量或数据规模。
- 主要方法。
- 对照组或基线。
- 关键条件与评价指标。
- 可获取的数据、代码或实验方案及其核实状态。

适合的画法：一个样本从输入到输出的过程；有对照时画并列路径，标出哪些条件相同、哪一项不同。
“对照组／基线”按具体实验呈现“共同设置 → 改变的模型或环节 → 判断依据”，使基线名称对应到实际比较中的作用；不只罗列名称。相同条件须有原文支持，不同实验与消融分别表达。
根据论文类型选择适合的表达：算法流程、实验分组、观察设计、理论假设与推导等，不把所有论文强套成机器学习流水线。
多次测量、样本数与独立实验次数不可混用。代码或数据入口放图注或来源记录，避免挤满画面。
细节卡用信息栏显示对象、数据来源和规模，中间画方法或实验过程，旁边展示对照及条件与指标；数据、代码或实验方案用核实后的可获取状态标记，并在图注给出入口。内容多时拆为连续编号的导航章节，例如“02 数据与研究对象”“03 方法如何工作”“04 基线怎样比较”。

## 3. 核心发现与证据

保留以下信息对应关系，按实际发现数量记录，不强制凑三条：

| 核心发现 | 对应图表、章节或页码 | 关键数据或观察 | 成立条件 |
|---|---|---|---|
| 每条发现用短句表述 | 只填已核对的位置 | 保留单位和比较对象 | 任务、样本、协议或关键假设 |

适合的画法：关键对照、准确的小型结果图、论文实际观察的并排展示。
指标增大或减小是否更好要标明；分数差、百分点与相对百分比不混淆。
有不确定性信息且会影响解读时保留；不能凭图形美化生成误差线、显著性标记或不存在的观测。
理论论文可画“假设 → 命题 → 适用范围”，定性研究可画“观察 → 证据 → 解释”，不强行构造实验数字。
细节卡让每条发现对应一组证据：发现短句、对比图或关键观察、成立条件，以及可核对的图表／章节／页码。可每条发现一张图；不把宽表缩成无法阅读的小字。

## 4. 创新与贡献

分别整理：

- 作者声称的创新。
- 解读者认为有证据支持的贡献。
- 与已有工作的具体区别。

适合的画法：在已有流程旁高亮新增加或改变的环节，并连接其支持证据。
“作者声称首次”不能直接改写成“首次”；没有足够文献核查时保留归属。
解读者判断明确标注为判断，不能以用户口吻虚构“我认为”。
细节卡保留“作者声称”“证据支持”“具体区别”三个区分清楚的区域，用差异示意或证据连线连接它们。

## 5. 局限与待确认问题

分别整理：

- 作者承认的局限。
- 解读者识别出的局限及依据。
- 证据尚不足的判断。
- 需要查证的问题。

适合的画法：适用与不适用条件、已验证与未验证区域，或从关键结论延伸出的限制标记。
“原文未说明”“当前材料未覆盖”“尚未核对”分开记录。
缺少证据不能画成结论已经被推翻；未验证情形也不等于方法必然失败。
细节卡保留“作者局限”“解读者判断”“证据不足”“待查证”四类。没有已确认内容时注明对应状态，避免为填满版面编造批评。

## 6. 与用户研究的关系

仅在已有明确研究背景时整理：

- 关联的课题或具体研究问题。
- 可以借鉴的方法或设计。
- 可以支持或挑战的观点。
- 可能的后续研究。

适合的画法：“论文证据 → 用户问题 → 可尝试的下一步”。
连接线表明是直接证据、相似问题还是迁移设想；适用条件不匹配时说明差异。
没有研究背景时标注“待补充研究背景”，继续完成论文图解。需要用户判断或用户主动要求此部分时，再用一个简短问题收集背景。
细节卡在有背景时保留“关联问题”“可借鉴设计”“支持／挑战观点”“后续研究”四项；没有背景时，HTML 与 Markdown 保留这些字段的待补充状态，不凭用户的一般身份推断当前研究题目。

## 导览章节与讲解稿的对应

首页先显示基本信息、一句话总结及全篇主线，再给出 01–0n 章节入口。章节沿上述内容骨架或用户指定的原文顺序展开。
简单论文可以六章对应六部分；方法复杂时，可以拆成下列八章：

| 导航示例 | 所属内容 | 弹窗覆盖 |
|---|---|---|
| 01 研究问题与背景 | 研究问题与背景 | 四个小项 |
| 02 数据与研究对象 | 研究设计与方法 | 对象／来源、规模 |
| 03 方法如何工作 | 研究设计与方法 | 方法过程、可获取资源 |
| 04 基线怎样比较 | 研究设计与方法 | 对照、关键条件与指标 |
| 05 核心发现与证据 | 核心发现与证据 | 发现、位置、观察、成立条件 |
| 06 创新与贡献 | 创新与贡献 | 作者声称、证据支持、具体区别 |
| 07 局限与待确认 | 局限与待确认问题 | 四类限制与未知 |
| 08 与我的研究的关系 | 与我的研究的关系 | 四项联系或待补充状态 |

这是拆分示例，不强制八章。数据、方法、基线等具体章名随论文变化。HTML 与 Markdown 使用同一份章节清单。
在 Markdown 中，编号标题下先连贯讲解本章，再按需保留小项、公式、证据表与来源。不要把小项仅当内部清单，也不要把讲解稿写成只有字段的空表。
